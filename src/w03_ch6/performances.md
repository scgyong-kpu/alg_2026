## 눈여겨볼 만한 점

- 일반 데이터에서 버블 정렬, 선택 정렬, 삽입 정렬은 모두 입력 크기가 커질수록 시간이 빠르게 증가한다.
- 데이터의 크기가 2배 증가하면 실행 시간은 대략 4배 증가한다.
- 같은 50000개 일반 데이터에서 선택 정렬은 삽입 정렬보다 조금 빠르고, 삽입 정렬은 버블 정렬보다 빠르다.
- 버블 정렬은 nearly sorted 데이터에서 시간이 크게 줄어든다.
- 선택 정렬은 nearly sorted 데이터에서도 시간이 거의 줄어들지 않는다.
- 선택 정렬은 입력 상태와 관계없이 남은 구간 전체를 끝까지 비교해야 한다.
- 삽입 정렬은 nearly sorted 데이터에서 시간이 매우 크게 줄어든다.
- 삽입 정렬은 제자리를 빨리 찾으면 왼쪽 비교를 일찍 멈출 수 있다.
- Tokuda gap 수열을 사용한 Shell sort는 50000개 일반 데이터를 약 0.048초에 정렬해, 앞의 O(n^2) 정렬보다 매우 빠르다.
- Shell sort는 100만 개 일반 데이터도 약 2.618초에 정렬할 수 있어 더 큰 입력 크기까지 측정할 수 있다.
- Shell sort도 nearly sorted 데이터에서 빨라지지만, 모든 gap 단계를 수행하므로 삽입 정렬만큼 극적인 차이는 나타나지 않는다.
- Shell sort의 성능은 gap 수열에 영향을 받는다. 수업 시각화는 이해하기 쉬운 Hibbard 수열을, 이 표는 성능 측정에 Tokuda 수열을 사용한다.
- 성능 측정 결과는 알고리즘뿐 아니라 데이터의 성격에도 크게 영향을 받는다.
- Heap sort는 입력 상태와 관계없이 O(n log n)을 보장하지만, 이번 구현의 500000개 일반 데이터에서는 Shell sort의 0.747초보다 느린 0.983초가 나왔다.
- 사용자 환경의 측정에서는 750000개부터 Heap sort가 Shell sort보다 빨랐고, 1000000개에서도 Heap sort가 2.031초로 Shell sort의 2.514초보다 빨랐다. 한 번의 측정만으로 일정한 역전을 단정할 수는 없지만, 차수가 낮은 Heap sort가 n이 충분히 커지면 결국 역전할 것을 짐작할 수 있다.
- 이 한 번의 측정은 Shell sort가 언제나 더 빠르다는 뜻이 아니다. gap 수열, 입력 분포, Python 구현의 함수 호출·대입 비용이 실제 실행 시간에 영향을 준다.
- [3n log2(n)과 n^(4/3) 비교 그래프](https://www.wolframalpha.com/input?i=y+%3D+3xlog%282%2Cx%29%2C++y%3Dx%5E%284%2F3%29%2C+x+from+1+to+1000&lang=ko)는 범위를 1000, 10000, 100000, 200000으로 늘려 보며 두 성장률의 차이를 관찰한다. n^(4/3)은 Shell sort의 보장 복잡도가 아니라 비교를 돕는 경험적 곡선이다.
